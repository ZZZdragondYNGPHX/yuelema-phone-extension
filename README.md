# 约了吗小手机 v1.0.8（发布审核版）

这是现代现实都市「约了吗」MVU 角色卡的配套 SillyTavern UI 扩展。软件层承担推荐、线上短文本私聊、匹配、群组浏览、角色创作与面基约定；现实见面、约会及复杂长文本剧情仍由酒馆正文推进。

当前成果已通过本地静态检查与 Node 回归，尚未完成 SillyTavern 真机验收，不得据此宣称已在酒馆内发布可用。

> 连接预设、提示词预设和功能绑定可保存在本浏览器；首次使用会写入 20 份可编辑的默认提示词预设，重开连接页会自动载入默认连接预设。API Key 按连接预设 ID 保存到当前浏览器的独立缓存，绝不导出、写入 MVU 或回显；可在连接页删除当前 Key。真实认证、CORS、模型接口与扩展生命周期仍待目标酒馆版本验证。

## 当前已实现

- 悬浮圆形入口、可关闭且支持鼠标/触摸拖动的小手机窗口，以及“发现 / 匹配 / 消息 / 社区 / 我的”五导航（约伴导航为五击解锁的隐藏第六入口）。窗口右下角支持自由拉伸：鼠标按住即可调整宽高，触屏长按拉伸角后拖动；最小保持当前布局的原始尺寸，最大铺满实际可视浏览器界面，手机 / 电脑尺寸分别保存在当前浏览器。页头提供手机端 / 电脑端布局切换：手机端为底部导航单列，电脑端为左侧导航 rail + 各页多栏工作台。电脑右键悬浮球或手机持续长按十秒会在入口旁打开安全工具栏：“归位原位”同时清除悬浮球、面板位置和窗口尺寸缓存，“复制诊断”只复制点击、打开、MVU 可读状态、视图生成、DOM 子节点数量与面板几何，不包含 API Key、`stat_data` 原值、角色资料或聊天正文。
- 设计系统 2.0：`style.css` 单文件按 tokens → themes → base → components → shell → pages → desktop → motion 八分区组织；SFW 浅色 / NSFW 深色双主题语义令牌，品牌渐变、统一焦点环与 44px 命中热区；`src/ui/` 组件库提供按钮、列表行、徽章、分段控件、BottomSheet（电脑端自动升级为居中 Dialog）、空态、骨架屏与 SVG 图标。电脑端在 ≥760px 门禁内展开各页工作台（发现媒体+档案、匹配工具+已牵手、消息收件箱、我的仪表盘、创作两/三栏、图片素材侧栏等）；≥1080px 私聊升级为“会话列 + 会话 + 可折叠公开资料上下文栏”三列 master-detail。`prefers-reduced-motion` 与宿主 `body.reduced-motion / no-blur / noShadows` 开关全部支持降级。
- SFW / NSFW 五击解锁门：连续点击“关于软件”五次只显示右侧点击式开关，实际切换由开关通过受控 MVU 管线完成。SFW 保持非露骨表达；NSFW 允许明确成年、自愿且边界清楚的直接调情、欲望讨论与线上文爱，不再把成人表达强制改写成含蓄暧昧；内容尺度不替代明确同意、成年人校验或边界记录。
- 首页只保留毛玻璃候选角色卡：公开资料、关键词与喜欢 / 不喜欢 / 收藏 / 刷新四个操作；快速模型候选的昵称必须是自然人的个人姓名，不能是玩家、AI、系统、职业或概念标签。喜欢 / 不喜欢成功保存后才自动生成下一位；收藏、取消收藏只保存当前状态，不额外生成角色；刷新只生成下一位且不改变权重。首页的喜欢/不喜欢只学习公开标签偏好，不会建立匹配或会话；收藏把对象留入收藏夹。空池卡片的刷新调用 `recommendation_refresh` 绑定的快速模型。
- 角色创建入口已迁移到“我的”。“我的 → 设置 → 图片管理”提供浏览器本地图片库：可导入本地 PNG/JPEG/WebP（压缩后保存），也可点击“下载并保存到图片库”后在独立弹窗填写 HTTP/HTTPS 图片链接并确认；主面板不常驻链接输入框。每张图可维护 `-5…5` 整数关键词权重，通过桌面右键或移动端长按打开“编辑匹配关键词”，并可在编辑窗口删除图片。图片管理标题右侧把纯文字“生图”按钮放在“设置”左边；点击后进入带独立标题与返回路径的生图子界面，不再与图片库工作台同时显示。子界面可选择已配置的 NovelAI、OpenAI-compatible 或 ComfyUI，输入本次提示词并“生成并保存”。人物提示强制附加成年人约束，结果经安全解析与本地压缩后直接加入图片库，不写 MVU。可将全部图片与逐图关键词权重导出为版本化 JSON 图包，换设备时再合并导入；相同图片会跳过，ID 冲突自动改名，现有图片不会被覆盖。“设置”按钮仍只打开图片匹配设置；生图工作界面另有“接口设置”直达生图配置。`image_match` 只读取候选人的公开资料与图片库已有关键词；LLM 失败时回退本地关键词裁决。首页候选卡背景、首页头像和候选公开资料头像使用最高匹配图片，无结果时保留原渐变与姓名首字头像。
- 公开标签长期偏好、本地双层匹配、匹配会话与短文本私聊；SFW / NSFW 各自维护独立关键词权重，模型只提出受限关系变化与语义分类，程序校验并提交。
- 首页空池生成、首页刷新、灵魂匹配和描述匹配在候选公开资料通过严格校验后，会在同一次用户操作中非阻塞启动图片匹配 LLM；图片选择不等待、不阻塞对应模块 LLM 的角色生成、受控 MVU 写回或会话创建，拒绝和超时只影响展示回退。
- “消息”一级页是独立会话列表：时间倒序、本地已读水位与未读徽章、长按/右键置顶菜单、新牵手 rail 与页头展开式搜索。点入后进入私聊详情：时间分组与连续气泡合并的消息时间线、联系人卡、会话内打字指示，电脑端还有常驻会话列与可折叠的对方公开资料上下文栏。发送进入等待态和 AI 回复完成后的重渲染会读取、恢复真正滚动的内层消息时间线；原本在底部则继续跟随新底部，原本向上阅读则保留阅读位置。
- 私聊、群聊与论坛生成成功的会话图片及其窄场景结构会保存到独立浏览器本地缓存，刷新、重开网页或重新挂载扩展后按“界面 / 会话 / 消息”恢复，不写入 MVU、图片素材库或设置导出。“生图设置 → 查看图片缓存”可回顾原图、查看结构化语句或逐张确认删除；聊天内仍显示适合阅读的小图，电脑右键 / 手机长按后可选择查看结构化语句或在可滚动窗口中按原始像素查看大图。NAI、OpenAI-compatible 与 ComfyUI 分别使用独立连接/提示词配置；OpenAI 请求只发送标准图片接口字段，固定负面要求会转换进自然语言 prompt。
- “消息”一级页支持按昵称或最近一条可见消息搜索；私聊详情右上角提供 `…` 更多菜单。“清空聊天记录”承接旧会话删除语义，仅移除会话并按关系状态安全处理已匹配/已拉黑关系；“删除角色”会在一次受控 Patch 中删除该角色在推荐、角色池、会话、面基记录和群组中的全部 MVU 引用，但不会删除浏览器图片库、角色模板等设备侧数据，也不会回退 UID 计数器。AI 的 `replies` 会拆成多条消息气泡；每次真正角色回复会按当前模式给出受限语义、强度与增减方向，再由本地程序至多改变友情 / 心动 / 欲望中的一项：单次最多增加 5、下降 10，正向数值越高增长越慢，且始终钳制在 `0–100`。输入栏右侧改为 Telegram 风格纸飞机：电脑端右键、手机端长按均可打开工具栏，左键/轻触仍发送；“约定面基”在没有可用路线前保持灰色不可点，达到门槛后按友情、恋爱或欲望路线生成草稿。点击私聊对象头像会打开其公开资料。发送与面基仍分别复用既有受控桥，面基只填入正文输入框、不自动发送。
- “我的 → 设置 → 对话总结”提供总开关、总结方案与总结档案：关闭时方案/档案入口不可交互，私聊模型收到当前保留的完整聊天记录；开启时可按 SFW/NSFW 分别绑定总结连接/提示词，设置每 `2–60` 个玩家/角色消息层自动总结及 `0–5` 次重试。总结成功后只在私聊顶部短暂提示，失败提示附带重新总结入口；右上角 `… → 聊天总结` 可查看、手动整理或重新整理单条记录。每段总结、锚定消息 UID、层数、状态与安全失败原因都通过受控 Patch 写入 MVU，私聊模型改用“历史总结 + 未总结后缀”。面基前会强制整理所有尚未总结的保留聊天，再把仅引用公开资料、已确认边界与会话总结的行动草稿填入正文输入框；仍绝不自动发送。
- v1.0.8 把正文经历与线上会话总结彻底拆开：每个正式角色在 `/正文记忆/{角色UID}` 拥有独立滚动摘要，角色入池/删除时同事务创建/清理；旧聊天首次私聊会以受控 Patch 补齐缺项并移除孤立项。私聊模型收到“当前对象第一手经历”和“其他对象第三人称经历”两个分区，不接收内部 UID，且被明确禁止把第三人的台词、同意、拒绝或身体经历认作当前对象亲历。废弃的 `会话.长期摘要` 与模型 `sessionSummary` 字段已从 Schema 和运行时合同删除。
- 个性化内容推荐设置位于“设置 → 隐私权限设置 → 个性化内容推荐管理 → 个性化内容偏好”；关键词权重保存在当前设备的开放学习库，并严格分为 SFW / NSFW 两套词库：切换模式不读取、复制或污染另一套。首页刷新会把当前模式全部关键词及 `-5…5` 权重、玩家公开资料与性别 / 性取向双向匹配条件交给既有推荐模型；AI 可自由生成新鲜、安全的公开标签，不受固定主题表限制。候选成功走完受控 MVU 写回后，未知公开标签自动以 `0` 收录，已有词保留当前权重；首页喜欢 / 收藏 / 不喜欢再按公开标签同步 `+3 / +1 / -3`（范围 `-5…5`）。关闭个性化后不会继续累积。收藏夹仅有“取消收藏”和“发起私聊”：后者由本地算法合成公开心动名片兼容度（性别/性取向、城市、意图、年龄段、距离）与关键词权重兼容度，再与角色创建页互动节奏的拒绝阈值比较；通过才建立私聊，未通过只保留婉拒结果、不创建会话。灵魂匹配和描述匹配分别使用当前模式的设备关键词权重与“临时权重覆盖同名本地权重”规则，随后由本地公开资料 / 关键词评分裁决；只有分数达到角色的取消匹配阈值才物化为已匹配关系、建立私聊并写入“已互相喜欢”，未达到时只记录婉拒 / `已取消` 角色，不进入消息，也不复用收藏角色。描述匹配原始输入与临时权重不会持久化或显示。
- 群组小程序已提供持续的聊天群与“心动社区”论坛：聊天群右上角 `⋮` 可创建/查找；创建页只可勾选已有私聊角色的公开资料并保存到浏览器本地。进入**特定聊天群**后，右上角 `…` 提供“退出群聊 / 清空群历史 / 自动更新设置”：退出删除该群的小程序本地数据，清空只删除群消息/临时成员/总结并保留该群自动更新配置；每个群分别手动设置开关与 `5–3600s` 间隔。群开启后只按本群定时器调用 `group_chat`，玩家发言不额外调用；关闭后才由玩家发言触发更新。心动社区的开关位于右上角“设置”，开启后在社区首页保持打开时每 30 秒仅更新**所有已有本地帖子**的标题/正文/标签，不新增帖子；新一批八频道帖子只能通过下拉刷新生成。小手机最顶部有可见的 `⠿ 拖动` 把手；论坛的真实内容滚动区明确允许手机手势和桌面滚轮。论坛首页仅在内容滚动到顶端时才允许刷新：手机端手指下拉到阈值后松开；桌面端在标题或帖子区域向上滚动鼠标滚轮累计到阈值、停滚后刷新；任意反向向下滚动或回拉都会取消。八个频道“今日心情 / 附近的人 / 同城瞬间 / 兴趣同频 / 深夜树洞 / 恋爱吐槽 / 约会报告 / 话题广场”均为可点击子区，点击后下方只显示对应本地帖子，再点高亮频道返回全部动态；每次 `forum` 首页刷新都要求模型恰好更新八个频道各一篇（各频道自带 note/brief 定位文案供提示词合同引用）。进入帖子后玩家评论才会触发本地讨论更新。群友、帖子作者与评论者均为严格校验的成年人公开关键资料；所有群组/论坛消息、临时角色、自动更新和帖子都存于专用浏览器缓存，不写入 MVU 或酒馆正文。
- 聊天群和论坛帖子复用“聊天总结”按钮及同一 `chat_summary` 绑定、楼层间隔和重试设置；它们的总结历史会与私聊一同出现在“我的 → 设置 → 对话总结 → 总结档案”，但只保存在专用浏览器缓存，不进入 `stat_data`。论坛首页没有总结入口。
- 面基在已匹配前提下，且当前模式允许的友情 / 恋爱 / 欲望路线至少一条达到门槛后才会解锁；记录会写入主导路线，并仅填入强调该路线的 `#send_textarea` 草稿。扩展不会自动点击或发送，玩家发送后由正文推进现实剧情。
- “我的”提供恋爱氛围的角色创建界面与模板库：手动创建、导入导出、占位 / URL / 本地压缩头像、AI 增量补全与 AI 完整创作。导入模板字段名可使用标准名，或在末尾附加半角冒号 `:` / 全角冒号 `：`；完整公开格式见 [角色模板格式说明](./角色模板格式说明.md)。登记后的角色先进入未展示候选池，不会立刻强插首页；只有当前模式存在与其公开标签同名的正权重关键词，且成年人、性别 / 性取向硬条件和本地匹配分同时通过时，首页刷新才会优先遇见它，灵魂 / 描述匹配才会将它提升为已匹配角色并建立私聊。个人资料编辑页不再保存头像引用；“我的”页头像可点击打开本地菜单，支持导入、填写图片链接或移除，且独立保存在当前浏览器，不写入公开资料、MVU、导出或提示词。页面右上角和两张 AI 卡片都提供独立“设置”入口；两种 AI 调用分别绑定，不再共用一个角色创作预设。AI 增量补全只填写空字段并补入不重复的新标签，保留已有字段、标签和头像；完整创作仍载入整份新草稿。两种创作和约伴角色生成的固定系统合同要求姓名自然分散，不得长期集中于任何单一姓氏；界面的姓名输入占位也不再提供固定人名样例。AI 只返回内存草稿，玩家审核并点击“验证并登记”后才进入受控 Patch。
- OpenAI-compatible 非机密连接预设、提示词预设（`depth / order / position / enabled / content`）、模型拉取及按功能绑定。首次加载会把推荐人物、私聊、聊天群、心动社区、AI 补全、AI 完整创作各自的 SFW / NSFW 默认预设写入本地提示词预设列表，之后可直接查看、编辑、删除或导出；连接预设与提示词预设字段相互隔离；API Key 单独保存在当前浏览器缓存，调用端会按预设 ID 自动恢复。

## MVU 运行前置与安全降级

- 本扩展的完整读写能力要求当前聊天已加载兼容的 MagVarUpdate/MVU 提供方，且 `window.Mvu` 至少暴露 `getMvuData`、`parseMessage`、`replaceMvuData` 及对应的 `Mvu.events.VARIABLE_UPDATE_ENDED`。
